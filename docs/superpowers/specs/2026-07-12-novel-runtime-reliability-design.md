# 小说运行时可靠性整改设计

## 目标

恢复小说模式的可测试性，并使批量写作的最终状态准确反映章节失败；不改变既有小说内容、LLM 提示词或质量判定规则。

## 范围

1. 将仓库可执行源码、测试与打包元数据中的 Python 导入统一为 `awp_rp_runtime_v3`。
2. 让小说测试可被 `pytest` 收集并执行。
3. 为 `BatchProgress` 增加可区分的部分失败终态；批处理完成后不再把失败批次覆盖为成功。
4. 为成功、完全失败、部分失败三个批处理终态补充测试。

## 非目标

- 不重写 `write_chapter()` 与 `write_chapter_stream()`。
- 不改变质量门控的接受/拒绝语义。
- 不迁移或修改已有 SQLite 小说项目数据。
- 不修改模型、Token 上限、提示词或外部 LLM 提供商配置。

## 设计

### 包名边界

仓库根目录作为 `awp_rp_runtime_v3` 包的源码目录。所有运行时代码、脚本、测试、打包入口和面向用户的示例统一使用该名称。历史档案文档保留原始 v2 名称，以免篡改历史记录。

### 批处理状态

`batch_write()` 在内存中累积失败章节索引。循环完成后：无失败为 `completed`；存在失败且至少写出一章为 `completed_with_failures`；全部章节失败为 `failed`。最终 `BatchProgress` 保存失败章节与可读错误摘要，调用方可据此续跑失败范围。

### 验证

测试先覆盖包导入与批处理三种终态，再修改运行时代码。完成后运行小说测试集和全量测试收集；使用 `compileall` 作为额外语法检查。

## 风险与兼容性

包名变更可能影响外部 ComfyUI 安装路径，因此本期在 README 中明确新的安装目录与入口。SQLite schema 和已存在的状态值不变；新增状态是向前兼容的字符串值，旧消费者仍可将非 `completed` 状态视为需要关注。
