# 小说版 Coding 网页工作台设计

日期：2026-07-26
状态：已完成对话设计，等待书面规格复核

## 1. 产品目标

把当前终端 TUI 替换为一个本地运行、浏览器访问的专属小说创作工作台。
它不是普通后台管理页，也不是让 AI 自主编剧情的聊天壳，而是“作者主导、
编辑深挖、项目管线写作”的小说版 Coding：

- 作者拥有剧情、人物选择、章节目的和最终批准权。
- 专属编辑通过追问、质疑和反例榨取作者意图，不奉承，不用套路替作者做决定。
- 编辑对话负责形成作者计划，不直接生成整章正文。
- 只有经过独立批准和执行两个动作的作者计划才能进入 Writer 管线。
- 对话、计划、提示词、正文版本和管线事件全部本地持久化。
- 网页提供真实流式输出和管线可见性，不使用假打字动画。

## 2. 非目标

- 不恢复 RP Mode、ComfyUI 节点或旧 Session 管理。
- 不把项目拆成额外的外部 Agent 服务。
- 不在浏览器中暴露任意文件路径、Shell 或不受限工具。
- 不显示模型私有思维链；只展示面向作者的结构化依据、问题和结果。
- 不让 Prompt 修改影响已经开始的任务。

## 3. 主界面

采用已确认的 B 方案：“小说版 Coding 工作台”。

### 3.1 固定三栏

1. 左栏：项目树
   - 项目切换
   - 全书编辑室 / 本章对话切换
   - 总纲、世界观、人物卡、伏笔与账本
   - 章节树和章节状态
   - 提示词工作室
2. 中栏：编辑协作
   - 无论章节是否已有正文，中栏始终是作者与编辑的对话
   - 编辑问题、作者消息、计划卡片、批准事件和管线事件使用不同消息类型
   - 底部固定多行输入框，支持停止当前生成
3. 右栏：工作成果
   - 计划、正文、批注三个标签
   - 正文流式写入
   - 资料和正文默认只读，可显式进入编辑模式
   - 底部显示字数、版本和管线阶段

窄屏时保留中栏；左栏折叠为抽屉，右栏通过标签或抽屉打开。桌面版本优先适配
常见 1366×768 和 1440×900 工作区。

### 3.2 对话组织

- 每本书有一条“全书编辑室”对话，用于题材、总纲、人物、世界观和跨章问题。
- 每个章节有独立编辑对话，避免章节细节污染其他会话。
- 全书稳定资料可以进入章节上下文；章节临时讨论不会自动反写全书设定。
- 浏览器关闭或刷新不会清空会话；Pi 进程可重建，历史从本地事件恢复。

### 3.3 主题

全部提供并记忆浏览器选择：

- 默认：墨与纸。深墨色框架、暖纸面、克制砖红强调色。
- 石墨 Coding。深色工具外壳，正文区域保持浅色纸面。
- 白色工作室。明亮、现代、高对比的工作主题。

三套主题共享布局、字号层级和交互状态，不能成为三套分叉组件。

## 4. 作者工作流

### 4.1 构思和计划

1. 作者在全书或章节编辑室输入想法。
2. 消息先写入本地，再发送给 Pi。
3. 编辑流式回应，必要时生成“需要作者决定”卡片。
4. 编辑可以提取素材或保存等待确认的作者计划。
5. 计划卡片明确显示版本、已确认事件、未解决问题和来源。

### 4.2 批准和执行

- 支持自然语言授权，也支持明确按钮。
- “批准计划”和“交给 Writer”是两个不同动作和不同作者轮次。
- 点击按钮会生成可审计的规范化作者操作事件，不直接调用绕过授权的内部方法。
- 存在未解决问题、版本不是最新、来源哈希不符或语义含糊时禁止执行。
- Writer 只消费已批准计划的精确 ID、版本和内容哈希。

### 4.3 资料与正文编辑

- 总纲、世界观、人物卡、章节计划和正文默认只读。
- 点击“编辑”后进入明确编辑状态；离开时提示未保存变更。
- 保存不会覆盖旧内容，而是创建新版本。
- 资料修改同时更新项目文件和确定性存储，让下一轮编辑和 Writer 读取新版本。
- 手工正文修改保存为新的人工版本，保留 Writer 原稿和修改来源。

## 5. 提示词工作室

左侧提供“提示词”入口，包含 Editor、Architect、Writer、Continuity、
Mechanical Gate、Quality、Style Cleaner、Ledger 等实际角色。

- 默认只读，进入编辑模式后才能修改。
- 系统默认提示词与项目覆盖提示词分层显示。
- 每次保存生成不可覆盖的新版本，支持差异比较、恢复和取消项目覆盖。
- 保存前进行基本结构校验，防止空提示词或缺失必要契约。
- 正在运行的任务固定使用启动时的 Prompt 快照；修改只影响之后的任务。
- 每次计划、草稿和质量结果记录 Prompt 版本集合，保证结果可复现。
- 项目覆盖保存在项目目录内，不能接受浏览器提供的任意外部路径。

## 6. 技术架构

采用现有 React 18 + Vite 前端、aiohttp Python 服务器、SQLite 和嵌入式 Pi
Host，不增加独立 Agent 服务。

### 6.1 新组件

#### WorkspaceCatalog

扫描仓库 `novels/*/.novel_cli.json`，将 `project_id` 映射到经过校验的项目根目录、
数据库和状态。所有 API 和 WebSocket 连接先经过项目绑定，不相信浏览器传入路径。

#### EditorSessionManager

以 `(project_id, room_type, chapter_index)` 为键管理 Pi 编辑会话。一个房间同一时刻
只允许一个活动生成；浏览器连接与 Pi 生命周期解耦。无人连接后保留短暂宽限期，再安全
关闭 Host；重连时从本地历史恢复。

#### AuthorConversationStore

在 `.awp/authoring/conversations/` 中按房间追加 JSONL，保存：

- 作者消息
- 编辑最终回复
- 流式回复完成事件
- 素材和计划工具事件
- 批准、执行、停止和失败事件
- 单调递增的项目事件序号

未完成的流式片段不冒充最终编辑回复。消息写入失败时禁止向 Pi 发送。

#### VersionedDocumentService

只允许访问已登记的项目文档类型。当前版本写回正式文件或存储，历史版本进入
`.awp/versions/`。正文和 Prompt 使用同样的版本元数据，但分别采用独立契约。

### 6.2 实时通信

新增项目房间 WebSocket：

`/awp/ws/v1/novels/{project_id}/editor/{room}`

客户端发送：

- `author_message`
- `approve_plan`
- `execute_plan`
- `cancel`
- `resume_from`

服务器发送带 `event_id` 的事件：

- `author_message_saved`
- `editor_delta`
- `editor_message_completed`
- `decision_required`
- `author_plan_saved`
- `author_plan_approved`
- `pipeline_phase`
- `writer_delta`
- `quality_issue`
- `draft_version_saved`
- `turn_failed`
- `turn_cancelled`

断线重连通过 `resume_from(event_id)` 补发缺失事件。客户端按事件 ID 去重。服务端为慢
客户端设置有界队列；正文增量可以合并，批准、失败、保存等控制事件不能丢弃。

### 6.3 REST API

REST 负责非流式资源：

- 项目目录与项目详情
- 章节和房间历史分页
- 总纲、世界观、人物卡、账本
- 作者计划及版本
- 正文及版本
- Prompt 列表、版本、差异、保存与恢复
- 管线运行历史和失败详情

所有写接口使用结构化正文和已登记资源 ID，不接受磁盘路径。

## 7. 管线可视化

前端显示真实管线事件：

`计划编译 → Writer → 机械检查 → 连续性 → 质量判断 → 必要修订 → 账本 → 正式保存`

每个阶段显示等待、运行、完成、失败、跳过、耗时和面向作者的摘要。Writer 文本增量进入
右栏正文；质量问题和修订原因形成可定位卡片。author-led 模式中被设计为跳过的
Architect、Director 和自主 NPC 规划明确显示“按作者计划跳过”，不能伪装成已运行。

停止操作需要：

- 立即中断当前 Pi 或角色会话。
- 保留已写入的作者消息和未正式接受的临时正文。
- 不提交正式 Draft、Ledger 或其他副作用。

## 8. 错误处理与恢复

- Pi Host 启动失败：显示真实、经过长度限制的诊断和修复建议。
- WebSocket 中断：页面进入“重连中”，输入暂存本地，不重复发送未知状态消息。
- Writer 失败：批准计划保持批准状态，可在作者确认后重试，不自动改剧情。
- 质量拒绝：临时文本可查看，但明确标记“未通过管线”，且零正式副作用。
- 文档版本冲突：保存失败并展示服务器当前版本，禁止静默覆盖。
- Prompt 校验失败：保留编辑缓冲，不创建新版本。
- 服务器重启：从 JSONL、SQLite 和版本文件恢复，不依赖浏览器内存。

## 9. 本地启动

提供 Windows 启动器 `web.bat`：

1. 校验 Python、Node 和已安装依赖。
2. 启动本地 aiohttp 服务。
3. 等待健康检查成功。
4. 自动打开默认浏览器到 `/awp`。
5. 已有服务器运行时直接复用，不重复占用端口。

用户不需要进入 TUI。终端窗口可以最小化；后续可再增加托盘封装，但不属于首版。

## 10. 安全与权限边界

- 服务器默认只监听 `127.0.0.1`。
- WebSocket 与 REST 共享项目绑定和来源校验。
- Agent 没有 Shell、任意文件或网络工具。
- 浏览器不能提交项目根目录或输出路径。
- 日志不写 API Key，也不把连接配置返回前端。
- Prompt 编辑不改变 Python 的工具白名单和授权验证。

## 11. 测试策略

### Python

- WorkspaceCatalog 路径绑定和跨项目拒绝。
- 会话房间隔离、恢复、取消和并发限制。
- 对话 JSONL 先写后发、事件序号和重放去重。
- WebSocket 编辑流、Writer 流和断线续传。
- 按钮授权与自然语言授权使用相同安全边界。
- 文档、正文和 Prompt 版本不可覆盖。
- Prompt 快照在任务中途不变化。
- 管线失败和 Quality 拒绝零正式副作用。

### React

- 项目树、房间切换、三栏和响应式折叠。
- 流式增量合并、事件去重、重连和停止。
- 计划按钮状态与批准/执行分离。
- 默认只读、编辑模式、版本冲突和未保存提示。
- 三套主题、主题记忆和基本无障碍。

### 端到端

- 作者对话 → 计划 → 批准 → 执行 → Writer 流式正文 → 正式版本。
- 刷新页面后恢复对话、计划、正文和管线状态。
- 修改 Prompt 后仅下一次运行使用新版本。
- Host 崩溃、WebSocket 断开和 Writer 失败的可恢复路径。
- Chromium 桌面与窄屏浏览器验证。

## 12. 验收标准

- 双击启动器后可以在浏览器完成全部默认创作流程。
- 不输入技能名即可与专属编辑讨论。
- 编辑和 Writer 均真实流式显示。
- 全书与章节对话相互隔离并可恢复。
- 资料、正文和 Prompt 均有本地版本历史。
- 任何模糊、否定或矛盾消息都不能批准或执行计划。
- author-led Writer 结果可追溯到精确作者计划和 Prompt 快照。
- 管线运行阶段、失败和正式保存状态在网页中清晰可见。
- 现有小说项目可以打开，已有输出和作者记录不被覆盖。
