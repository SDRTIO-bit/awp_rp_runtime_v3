# 小说编辑 Agent 沙箱工具包设计

日期：2026-07-27
状态：已实施（2026-07-27）

## 1. 目标

为专属写作编辑 Agent 提供接近 Coding Agent 的项目工作能力，使它可以主动理解任务并自行选择工具，而不要求作者输入技能名、斜杠命令或固定格式。

工具只能作用于当前小说项目。编辑可以阅读、检索、创建和修改小说资料，但不能借助工具访问其他小说、仓库代码、用户目录、网络或系统资源。

本设计复用 Pi Coding Agent 的原生工具，通过执行前检测和审批降低实施成本，同时保留现有作者主导边界：

- 作者决定剧情、人物、章节目的和最终取舍。
- 编辑负责阅读、追问、质疑、整理、校对和维护资料。
- 编辑不能直接代写完整章节，不能批准自己的作者计划。
- Writer 仍只消费经过作者批准并独立执行的作者计划。

## 2. 能力范围

### 2.1 文件工具

向编辑开放 Pi 原生的以下能力：

- `ls`：列出项目目录。
- `find`：按名称查找文件。
- `grep`：检索正文、设定和资料。
- `read`：按范围读取文本。
- `write`：新建或完整写入文本文件。
- `edit`：对文本进行精确局部修改。
- `bash`：执行经过沙箱检测和审批的项目内辅助命令。

这些工具由模型按任务语义自动调用。网页不要求作者学习工具名称。

### 2.2 Agent 能力

主编辑保持长期项目会话，并增加项目任务委派能力。它可以把大范围阅读、设定核对、章节矛盾检查和资料归纳交给隔离的工作 Agent：

- 工作 Agent 使用独立 Pi Session，避免污染主编辑长期上下文。
- 工作 Agent 默认只拥有 `ls/find/grep/read`，不能写文件、执行终端、批准计划或启动管线。
- 工作 Agent 返回带文件路径和位置的证据摘要，由主编辑判断、追问或执行修改。
- 委派深度固定为一层，禁止工作 Agent 再创建 Agent。
- 每个委派任务具有文件数量、输出长度、模型轮次和超时限制。

主编辑是唯一可以申请修改小说文件的 Agent。所有 Agent 共享同一套项目根目录边界。

## 3. 执行前审批

Pi `tool_call` 事件发生在工具真正执行之前，并允许拦截器阻止调用。本项目在该拦截点增加 `NovelToolApprovalGuard`。

每个工具调用依次经过：

1. 参数规范化。
2. 项目绑定校验。
3. 路径和命令分析。
4. 风险分类。
5. 审批策略判定。
6. 执行或阻止。
7. 结果审计。

任何检测异常均采用失败关闭：不执行工具，并向编辑返回可说明的原因。

### 3.1 默认“替我审批”策略

默认策略不频繁打断作者：

| 风险 | 示例 | 默认结果 |
|---|---|---|
| 只读安全 | 项目内列目录、搜索、分段读取 | 自动批准 |
| 普通修改 | 新建笔记、修改纲要或设定文本 | 自动批准并备份 |
| 重要修改 | 覆盖正文、批量修改、移动或删除资料 | 前端请求作者审批 |
| 硬边界 | 访问项目外、网络、系统进程、内部状态 | 强制拒绝 |
| 无法判断 | 动态脚本、混淆命令、间接路径 | 拒绝；必要时提示改用明确工具 |

网页后续可切换为：

- `替我审批`：上述默认模式。
- `修改时询问`：所有写入和终端操作都询问。
- `严格只读`：仅允许安全读取和只读工作 Agent。

模式变更绑定当前小说项目并本地保存，不接受模型自行修改。

### 3.2 作者审批

需要作者判断时，Host 暂停该工具调用并产生结构化审批请求，网页显示：

- Agent 想做什么。
- 工具名称和规范化参数。
- 涉及文件。
- 风险说明。
- 可见的变更摘要或命令。

作者可以选择：

- 本次允许。
- 本次拒绝。
- 本会话允许同类操作。

“同类操作”由工具、规范化项目内路径范围和风险类型共同构成，不允许模型提交任意匹配表达式。审批具有超时；刷新、断线或服务重启后默认为拒绝。

## 4. 项目沙箱

### 4.1 根目录绑定

项目根目录只能来自服务器端 `NovelWorkspaceCatalog`，不能来自浏览器或模型参数。所有路径转换为项目根目录下的规范化相对路径，然后解析真实路径。

以下情况强制拒绝：

- 绝对路径。
- `..` 逃逸。
- 符号链接、Windows Junction 或其他重解析点逃逸。
- 大小写、短路径名或分隔符变化造成的根目录外路径。
- 跨小说项目访问。
- 通过 shell 环境变量、命令替换或子进程间接构造外部路径。

### 4.2 受保护内容

通用工具不得写入：

- `novel.db`、`novel.db-*` 及数据库伴随文件。
- `.novel_cli.json`。
- `.awp/authoring/**`。
- `.awp/pi-*/**`、Session 文件和运行时状态。
- 项目绑定、审批策略、审计日志和文件历史。

这些内容继续由现有 Python 专用服务写入。通用工具可以读取对编辑有意义的作者资料视图，但不能绕过合约改写计划、批准状态或运行记录。

### 4.3 文本写入和版本

- 通用写入只接受 UTF-8 文本和允许的合理文件大小。
- 修改已有文件前，将旧内容和内容哈希写入项目内受保护历史区。
- `edit` 使用读取时的内容哈希进行乐观并发检查；文件已变化时拒绝覆盖。
- 删除采用项目内回收站，不直接永久删除。
- 审批和工具审计记录参数摘要、决策、目标、变更哈希、Agent 和时间，不记录不必要的完整私密正文副本。

## 5. Bash 边界

仅凭字符串黑名单无法把任意 Shell 变成可靠沙箱。因此 `bash` 不直接执行未经分析的任意命令。

第一版采用命令能力分类：

- 自动允许：在项目目录内工作的只读文本和版本检查命令。
- 审批后允许：输入输出均能确定落在项目内的格式化、校验和批量文本命令。
- 强制拒绝：网络访问、包安装、注册表、服务、进程启动、计划任务、凭据读取、设备访问、外部工作目录和无法静态确定路径的命令。

文件创建和修改优先使用 `write/edit`，搜索优先使用 `find/grep`。当命令不能被可靠证明安全时，审批本身不能越过硬沙箱边界。

## 6. 系统组件

### 6.1 `NovelToolApprovalGuard`

位于 Pi Host 执行前拦截层，负责工具识别、参数规范化、风险判定和阻止。它不信任模型输出，也不把安全判断交给提示词。

### 6.2 `NovelProjectSandbox`

由 Python 实现项目绑定、真实路径校验、受保护路径、版本备份、回收站和审计。Node Host 在执行写操作前必须向 Python 请求能力令牌；令牌绑定请求 ID、工具、规范化目标、参数哈希和短有效期，不能复用到其他调用。

只读 Pi 工具仍需经过 Node 侧快速校验和 Python 项目绑定校验。所有实际写入保持“Python 是唯一项目状态写入者”的原则；Pi 原生 `write/edit` 的界面被复用，执行委托给 Python，而不直接调用 Node 文件系统写入。

### 6.3 `ToolApprovalBroker`

连接 Pi Host、Python 服务、WebSocket 和网页：

- 创建待审批请求并流式推送。
- 等待作者决定。
- 处理取消、超时、断线和重复响应。
- 在响应前不执行工具。
- 保证同一请求最多执行一次。

### 6.4 `ProjectWorkerAgent`

由主编辑通过专用工具创建只读、单层、限额 Session。Worker 的系统提示强调证据检索而非创作决定；其结果作为工具结果返回主编辑。

## 7. 网页表现

中栏对话流显示工具活动，但不泄露模型私有思维：

- 正在读取、搜索、修改或检查。
- 自动批准、等待审批、被拒绝或执行完成。
- 修改后的文件和简短差异摘要。
- 工作 Agent 的任务状态和证据结果。

待审批卡片固定显示在可见区域，不能因缩放或右栏内容变长而隐藏输入框。工具状态通过现有流式通道传输；审批期间作者仍可停止当前生成。

## 8. 错误处理

- 路径校验失败：阻止并给出项目内替代路径建议。
- 作者拒绝：将结构化拒绝结果返回 Agent，Agent 可调整方案，但不能重复轰炸同一审批。
- 超时或断线：拒绝并取消调用。
- 写入冲突：保留双方版本，不自动覆盖。
- Worker 失败：主编辑继续工作并说明未获得哪些证据。
- Host 重启：所有未完成审批失效，不恢复执行。
- 审计失败：写操作失败关闭；只读操作可返回明确的基础设施错误。

## 9. 测试与验收

### 9.1 沙箱测试

- 拒绝绝对路径、`..`、大小写变体、符号链接和 Junction 逃逸。
- 拒绝跨小说访问和受保护路径写入。
- 拒绝 shell 网络、系统和动态逃逸命令。
- 验证普通项目内读取、搜索、写入和精确修改。
- 验证备份、哈希冲突和回收站。

### 9.2 审批测试

- 安全读取自动通过。
- 普通写入按默认策略自动批准并留痕。
- 重要修改在决定前不执行。
- 拒绝、超时、断线和重复响应均不会执行。
- 会话级同类允许不能扩大路径和工具范围。

### 9.3 Agent 测试

- Worker 只能读取当前项目。
- Worker 不能写入、执行 bash、批准计划或创建子 Worker。
- 主编辑能收到带来源的结果。
- Worker 失败不破坏主会话。

### 9.4 端到端验收

在 `daily_high_school` 项目中，编辑能够：

1. 自动发现并读取 `outline.md`、`story_bible.md`、`world.md`、参考资料和章节输出。
2. 跨文件检索人物、事件和设定。
3. 经审批策略修改一个普通 Markdown 文件并保留历史。
4. 对高风险修改展示网页审批卡片，拒绝后文件不变。
5. 委派只读 Worker 检查跨文件矛盾并返回引用。
6. 无法读取或修改项目根目录之外的任何文件。

## 10. 实施顺序

1. 先用失败测试定义项目路径、受保护内容和审批状态机。
2. 实现 Python 沙箱、历史、审计和审批 Broker。
3. 接入 Pi 原生读写工具的执行前拦截；写入转交 Python。
4. 实现网页审批卡片和流式工具事件。
5. 增加只读 Worker Agent。
6. 运行 Python、Node、Web 构建和端到端测试。
7. 重启本地网页服务，使已有 Pi Session 加载新工具。

## 11. 实施结果

- Pi 编辑已获得 `read`、`ls`、`find`、`grep`、`write`、`edit`、受限 `bash` 和 `delegate_project_task`。
- 所有文件调用都由 Python 项目沙箱解析；普通文本写入保留历史和审计，章节正文修改进入网页审批。
- 网页支持本次允许、拒绝和本会话允许同类操作；断线、未知请求和重复决定均失败关闭。
- Worker Agent 只有四个只读工具，不能写入、运行终端、批准计划或继续委派。
- 相关验证通过：Python 29 项、Pi Host 23 项、Web 5 项及生产构建。
