# 受控正文修订与项目 Skill

## 当前正文与历史版本

“当前正文”只指数据库中该章最新的 `accepted` 版本。被拒绝、待处理或失败的草稿不会被编辑器读取、Writer 使用或导出。每次导出会把当前正文写入 `output/chapter_XX.md`，并在 `output/manifest.json` 写入章节版本、草稿 ID、哈希和导出时间；`output_pre_*` 是历史快照，不是当前正文。

## 三轮正文修订

1. 编辑先用 `read_chapter` 读取完整的当前接受版本，引用 `r{版本}:p{段落}` 和段落哈希，提交原文、替换文、理由、叙事影响与后续影响。
2. 作者在下一轮明确确认。编辑只能批准该已保存计划，不能同轮应用。
3. 作者在更后的一轮明确要求应用。系统在一个事务内再次检查章节版本和所有段落锚点，成功后创建新的不可变 `accepted` 草稿；原版本仍可读取。版本不匹配会返回冲突，而不会覆盖较新的正文。

作者直接在正文编辑器保存整章时，系统仍走受控的“作者整章替换”适配器并检查预期版本；不会复制旧版本的质量结论。

## 审计与处置

审计只使用可追溯证据。第一版会识别正文中显式的连续性标记，例如 `【道具:钥匙=在林舟手中】`，并检测同一事实键的不同状态，以及人物早于资料中的首次出场章节出现。每条发现都引用章节、版本与段落。

作者可以记录“接受修订、保留原样、暂缓”等处置。事实连续性矛盾不能标记为误报；只有未来的纯风格/机械规则允许范围化的误报例外。

## 项目 Skill

Skill 是项目内版本化的 Markdown，保存后仍默认未启用。作者必须在工作区的“技能库”显式启用，启用清单会使已有的空闲编辑会话重建，因此从下一轮消息开始生效。停用同样会在下一轮移除它。

编辑可以使用 `propose_project_skill` 提出 Skill，但不能写入 `agent/skills`、批准、保存为作者版本或启用它。Skill 不得请求新工具、扩展、Shell、网络访问或绕过作者确认；验证通过的启用版本才会提供给编辑 Host 和角色 Host。
