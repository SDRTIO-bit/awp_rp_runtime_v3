# AWP Novel Pipeline — 项目宪章与系统设计 (2026-07-25)

## 项目定义

> 一个保护人物微观因果、识别读者阅读摩擦，并把创作决策留给作者的小说生成系统。

这不是"AI小说去AI味生成与修复系统"。目标不是让文本通过检测器，而是让读者能顺着人物的眼睛、手和脚步一直读下去，不被迫停下来替作者解释。

## 核心转变

| 旧的隐含假设 | 新的设计目标 |
|-------------|-------------|
| 消除 AI 常见特征 → 文本更好读 | 消除阅读摩擦 → 读者能舒服地往下读 |
| 检测器通过 = 质量合格 | 读者不疑惑 = 管线有效 |
| 模型必须写得像真人 | 人物必须按自己的逻辑行动 |
| 越多审计越安全 | 越多人碰正文越像模型 |

拆解真人小说后的结论：读者可以容忍笨拙、套话和局部粗糙，却很难容忍人物不按自己的逻辑行动。句子偶尔普通不妨碍阅读，人物莫名其妙行动则直接打断阅读。

## 北极星指标

> 读者从第一段读到结尾，中间有几次不得不停下来替作者解释？

"阅读摩擦点"定义为：读者无法仅依据已经呈现的正文，自然理解人物行动、信息来源、规则变化或情绪推进，而需要回读、猜测、找补或暂时忽略的位置。

## 三层阅读模型

### 第一层：读者能否看懂发生了什么（Mechanical）

可自动检查、可自动修补：

- 人在哪、物品在哪、谁知道什么
- 时间、空间、人数和物体连续性
- 已建立规则与未完成任务
- 重复句和明显语病

### 第二层：读者能否理解人物为什么这么做（Micro-Causal）

可识别风险，不应自动修改：

- 人物眼下想完成什么
- 当前行动是否服务于这个目标
- 为什么不用更简单的方法
- 行动依据是否已在正文建立
- 行动后是否产生了可见结果

### 第三层：读者是否愿意接受这个人和这段关系（Creative Judgment）

只能给作者提供风险，决定权必须留在人手里：

- 越界行为有没有被正文承认
- 人物是否被剧情强迫行动
- 关系有没有抢跑
- 反感行为是否被包装成魅力
- 场景是否一直在操纵读者产生指定反应

## Mechanical Gate 与 Reader Comfort Review 分离

两者判断性质根本不同，**必须分开**，否则系统会再次越权。

### Mechanical Gate（客观一致性）

处理可以相对确定地判错的问题。自动打补丁。

范围：
- 时间矛盾
- 人数与位置错误
- 物体状态断裂
- 信息越权
- 已建立规则被违反
- 已到期任务被遗忘
- 明显重复、缺字和语病

### Reader Comfort Review（阅读风险）

处理存在创作判断的问题。**只输出风险报告，不自动修改正文。**

输出格式：
```json
{
  "friction_points": [{
    "quote": "原文",
    "likely_reader_question": "读者会问什么",
    "friction_type": "motivation_gap|info_gap|rule_conflict|character_boundary|relationship_rush|scene_overload",
    "reader_risk": "读者可能的负面反应",
    "intentionality": "accidental|intentional",
    "narrative_acknowledgement": "absent|partial|present",
    "productive_or_blocking": "productive|blocking",
    "severity": "high|medium|low",
    "author_decision_needed": true|false
  }]
}
```

关键区分：
- 好的不适：读者知道人物为什么这样做，但不一定赞同
- 坏的摩擦：读者连人物为什么这样做都不知道
- 系统应减少的是非预期的理解阻塞，不是消灭所有不适感

## 阅读摩擦不等于读者不舒服

### 应该减少的摩擦

- 读者不知道人物为什么突然行动
- 规则前后矛盾
- 关键信息没有建立
- 人物选择明显绕远，却没有理由
- 叙述把越界行为当成魅力，但正文没有意识到
- 场景必须靠读者自行补全才能成立

### 可以保留甚至需要制造的不适

- 角色主动做出错误选择
- 人物之间产生误会
- 主角表现出真实缺点
- 读者暂时不知道秘密答案
- 某个选择在道德上令人犹豫
- 冲突让读者担忧或生气

## 摩擦样本库结构

积累样本时不按"AI文本/真人文本"分类，而是混入：
- 写得顺的真人文本
- 写得差的真人文本
- 写得顺的AI文本
- 逻辑正确但人物僵硬的AI文本
- 文笔粗糙但因果流畅的文本
- 文笔漂亮但行动莫名其妙的文本

每条样本记录：
```json
{
  "text_span": "问题原文",
  "likely_reader_question": "读者会问什么",
  "friction_type": "motivation_gap|info_gap|rule_conflict|character_boundary|relationship_rush|scene_overload|action_overload|value_misalign",
  "reader_effect": "对阅读的具体影响",
  "intentionality": "accidental|intentional",
  "narrative_acknowledgement": "absent|partial|present",
  "productive_or_blocking": "productive|blocking",
  "mechanical_or_creative": "mechanical|creative",
  "severity": "high|medium|low",
  "confidence": 0.0,
  "author_decision_needed": true|false
}
```

## 项目宪章（冻结原则）

1. **系统优化阅读理解，不优化"像不像人写"。**
2. **Mechanical Gate 只处理可验证的一致性错误。**
3. **Reviewer 可以提出读者问题，不替作者决定答案。**
4. **不以消除不适为目标，只减少非预期的理解阻塞。**
5. **Review 结果优先校准 Architect，不直接转化为 Writer 禁令。**
6. **单篇样本不推动规则更新，只有重复出现且经人工确认的问题才进入系统设计。**
7. **任何新自动化都必须证明它减少了阅读摩擦，而不是仅提高了某个评分。**

## 当前架构（V4 — 2026-07-25）

```
Architect（规划阅读路径）
      ↓
Writer（生成正文）
  模型: agycli-gemini-3.1-pro-high
  提示词: 5 条读者导向原则（不包含反AI味/真人度/松弛度等概念）
      ↓
Quality Gate（格式/长度/空输出）
      ↓
Continuity（连续性检查）
      ↓
Mechanical Gate（HARD 审计）
  时间/人数/物体/信息越权/规则违反/未完成任务
  有硬伤 → 精确补丁 → 验证一次
  无硬伤 → 直接通过
      ↓
存盘 + Ledger Curator
```

已从热路径移除：
- Director V2（约束压缩 → 与 Architect 职责重合）
- Writer 内部状态表（提前规划 → 人物替章节完成 KPI）
- 运行时参考标杆（模仿表面特征 → 反而制造 AI 味）
- DESIGN 审计（设计过载 → 创作选择，不应自动修补）
- STYLE 审计（AI 味删除 → 统一文风 = 统一为模型腔）

已有旁路工具：
- `novel_cli audit-design <chapter>` — 只报告设计过载，不修改
- `novel_cli audit-style <chapter>` — 只报告 AI 味，不修改

待建设：
- `novel_cli review-comfort <chapter>` — Reader Comfort Review

## 已有工作的重新分类

### 保留的交集部分（既是 AI 问题也是阅读摩擦）

- 限知视角与人物知识隔离
- 时间、空间、人数和物体连续性
- 已建立规则与未完成任务追踪
- 重复解释与信息冗余识别
- 精确补丁和确定性应用
- 原稿、修改稿和审计记录留存
- 不让修复模型擅自改剧情

### 降级的非交集部分（可检测 AI 特征，不能证明读者更舒适）

- AI 味评分
- 真人度判断
- 禁用词大全
- 固定对话或描写比例
- 生理反应词频
- 象征数量配额
- "松弛度"配额
- 自动删除所有总结句
- 刻意为避免模板而制造随机性
- 多模型连续润色

## 评估指标

### 系统稳定统计

1. **无依据行动数**：关键行动发生前，正文是否建立了直接理由
2. **读者补洞数**：读者需要自行解释多少制度、动机和空间关系
3. **作者推手数**：多少节点依赖"正好出现的人"、"临时增加的规则"、"权威角色精准安排"

### 人工评价

4. **未承认的好感损伤**：人物做了可能让读者反感的事，但正文却把它当成幽默、浪漫或可靠
5. **继续阅读意愿**：读完本章后是否想读下一章；想知道的具体问题是什么

## 下一阶段（不迭代管线）

优先积累摩擦样本库——对 V4 生成的 Chapter 1 逐段标注：哪句话让读者必须回读、推测或替作者找补。

先验证 Reader Comfort Review 能否稳定回答两个问题：
1. 它指出的位置，真人读者是否真的会停顿？
2. 它能否区分"有效的不适"与"理解阻塞"？

等积累几十条样本后，Reviewer 的审计提示词会自然浮现，而不是凭空设计。
